# StudyForge: AI Personal Notes + Study Packs

Capture notes by text or voice, then turn them into **summaries, flashcards and exam-style practice questions**. Study packs are generated by a model adapted with **Adaption** (Adaptive Data + AutoScientist), and compared side by side with a general-purpose LLM.

Built for the **Build54 × Adaption** hackathon.

**Django 5 · DRF (function-based views only) · PostgreSQL · Redis · Celery · S3/MinIO · Groq · Adaption · Docker · GitHub Actions**

```
Client ──► Django/DRF API ──► PostgreSQL        (notes, study packs, FTS index)
                │  └────────► S3 / MinIO        (audio)
                └─ enqueue ─► Redis ─► Celery workers ─┬─► Groq Whisper         (voice → text)
                                                       ├─► Groq LLM             (naming, summaries, generic study packs)
                                                       └─► Adaption model       (adapted study packs)
```

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the design decisions.

## The problem

Students take messy notes, run out of time to revise, and don't know how they will be tested. Generic AI helps, but it doesn't know the exam style.

| Student problem | StudyForge feature |
|---|---|
| Notes pile up as "Untitled 37" | AI auto-naming + full-text search |
| Hard to write notes while the lecturer talks fast | Voice → text capture |
| Long notes are slow to revise | AI summaries |
| Passive reading doesn't stick | Flashcards for active recall |
| Students don't know how they'll be tested | Exam-style multiple-choice questions |
| A semester of notes is too long for one model call | Automatic chunking |
| Sharing with a study group is awkward | Public share links |
| Generic AI doesn't match the exam style | Model adapted on task-specific data |

## How Adaption is used

Adaption powers **study-pack generation only**. Voice → text, naming, search and sharing do not use it.

```
Idea → raw data → Adaptive Data → adapted dataset → AutoScientist → adapted model → StudyForge
```

1. **Raw data:** note chunks (100-300 words) paired with a summary, 5 flashcards and 3 practice questions in a fixed format.
2. **Adaptive Data:** imports and shapes the dataset (tone, length, grounding) and reports quality signals. Weak examples are removed.
3. **AutoScientist:** trains a small model (under 10B parameters) on the adapted dataset and evaluates it.
4. **StudyForge:** the study-pack task calls the adapted model.
5. **Comparison:** the same held-out notes go through the generic LLM and the adapted model, and the results are shown side by side.

### Generic vs adapted

Each entry can hold two study packs, one per provider:

| `provider` | Backend | Role |
|---|---|---|
| `generic` | General-purpose LLM on Groq | Baseline |
| `adapted` | Model trained with Adaption AutoScientist | The model under test |

Both get the same instruction and return the same cleaned JSON shape, so the comparison is fair.

### Long notes

Notes are split into chunks of about 200 words (never more than 300). Headings start a new chunk, and one sentence overlaps between chunks so ideas aren't cut in half. Each chunk is processed separately (up to `STUDYPACK_MAX_CHUNKS`, default 10), then summaries are joined and duplicate flashcards and questions are removed.

## Quick start (Docker)

```bash
cp .env.example .env
make up                       # api :8000, worker, beat, postgres, redis, minio
make superuser                # optional, for /admin/
open http://localhost:8000/api/docs/   # Swagger UI
```

Runs fully offline by default using **fake AI providers**, so no API keys are needed to try it.

### Using real providers

```
# Voice → text and LLM (naming, summaries) via Groq
AI_STT_PROVIDER=apps.ai.providers.groq_provider.GroqSTTProvider
AI_LLM_PROVIDER=apps.ai.providers.groq_provider.GroqLLMProvider
GROQ_API_KEY=gsk_...
GROQ_LLM_MODEL=openai/gpt-oss-120b
GROQ_STT_MODEL=whisper-large-v3-turbo

# Study packs
STUDYPACK_GENERIC_PROVIDER=apps.study_packs.providers.GroqStudyPackProvider
STUDYPACK_ADAPTED_PROVIDER=apps.study_packs.providers.AdaptionStudyPackProvider
ADAPTION_BASE_URL=...
ADAPTION_API_KEY=...
ADAPTION_MODEL_ID=<your-adapted-model-id>
```

> Check the [Adaption docs](https://docs.adaptionlabs.ai/) for how your trained model is served, and adjust `AdaptionStudyPackProvider` in `apps/study_packs/providers.py` to match. An OpenAI provider (`openai_provider.py`) is still available as an alternative.

## API (all under `/api/v1`)

### Auth

| Method | Path | Purpose |
|---|---|---|
| POST | `auth/register/` `auth/login/` `auth/refresh/` `auth/logout/` | JWT auth (refresh rotation + blacklist) |
| GET/PATCH | `auth/me/` | Profile |
| POST | `auth/password-reset/` · `auth/password-reset/confirm/` | Reset flow |

### Notes

| Method | Path | Purpose |
|---|---|---|
| POST | `capture/` | **Capture first**: text or audio; creates + AI-names a container if none given |
| GET/POST | `containers/` | List (cursor-paginated) / create |
| GET/PATCH/DELETE | `containers/{id}/` | Rename, archive, delete |
| GET/POST | `containers/{id}/entries/` | Timeline / add text or audio (**202 Accepted**, poll `status`) |
| GET/PATCH/DELETE | `entries/{id}/` | Edit text/transcript (re-runs AI), delete |
| POST | `entries/{id}/retry/` | Retry a FAILED entry |

### Study packs

| Method | Path | Purpose |
|---|---|---|
| POST | `entries/{id}/study-pack/?provider=generic\|adapted` | Generate a study pack. **202 Accepted** |
| GET | `entries/{id}/study-pack/status/?provider=generic\|adapted` | Poll progress and fetch the material |
| GET | `entries/{id}/study-pack/compare/` | Generic and adapted packs side by side |

`provider` defaults to `generic`. Re-posting regenerates that provider's pack.

### Summaries, sharing, search, health

| Method | Path | Purpose |
|---|---|---|
| POST | `containers/{id}/summary/` | Async AI summary: `today/yesterday/week/month/all/custom` |
| POST/DELETE | `containers/{id}/share/` | Publish / unpublish |
| GET | `public/{public_id}/` | Anonymous JSON of a public container |
| GET | `/share/{public_id}/` | Anonymous server-rendered web page |
| GET | `search/?q=&container=` | Full-text search with highlighted snippets |
| GET | `/health/live/` `/health/ready/` | Probes |

### Lifecycles

```
Entry:      pending → transcribing → analyzing → completed | failed
StudyPack:  pending → generating → completed | failed
```

While generating, `chunks_done` / `chunk_count` show progress.

## Example workflow

**1. Capture a note**

```bash
curl -X POST http://localhost:8000/api/v1/capture/ \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Photosynthesis is the process by which plants convert light energy into chemical energy...",
    "container_name": "Biology 101"
  }'
```

**2. Generate study packs with both models**

```bash
curl -X POST "http://localhost:8000/api/v1/entries/5/study-pack/?provider=generic" -H "Authorization: Bearer TOKEN"
curl -X POST "http://localhost:8000/api/v1/entries/5/study-pack/?provider=adapted" -H "Authorization: Bearer TOKEN"
# 202 Accepted
# { "id": 1, "entry": 5, "provider": "adapted", "status": "pending", "summary": "",
#   "flashcards": [], "exam_questions": [], "chunk_count": 0, "chunks_done": 0 }
```

**3. Compare the results**

```bash
curl http://localhost:8000/api/v1/entries/5/study-pack/compare/ -H "Authorization: Bearer TOKEN"
# 200 OK
# {
#   "entry": 5,
#   "generic": { "provider": "generic", "status": "completed", "summary": "...", "flashcards": [...], "exam_questions": [...] },
#   "adapted": { "provider": "adapted", "status": "completed", "summary": "...", "flashcards": [...], "exam_questions": [...] }
# }
```

Each flashcard is `{"q": "...", "a": "..."}` and each exam question is `{"question": "...", "options": ["...", "...", "...", "..."], "answer": "B"}`.

## Deploy

CI (`.github/workflows/ci.yml`) runs lint → migrations check → tests (Postgres service, ≥80% coverage) → builds and pushes
the `runtime` image to GHCR on `main`. `deploy.yml` then rolls it out over SSH using `docker-compose.prod.yml`
(swap for ECS/Fly/K8s as needed). Required secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`.

## Layout

```
config/            settings (base/dev/prod/test), urls, celery app
apps/common/       base models, cursor pagination, throttles, error envelope, health

tests/             pytest suite
docs/              architecture and deployment notes
```
